- 修复 Windows 微软拼音输入法重复上屏（子模块 `third/ghostty_dart`）：
  - 症状：中文组字时每个按键都把整段预编辑串再送一遍给 shell（输入 `nihao` 实际送入 `n`、`ni`、`ni h`、`ni ha`、`ni hao`，且各出现两次）。
  - 根因：Windows TSF 以**折叠组合区**开始组字（`TextEditingDeltaNonTextUpdate`，composing 2..2），我们的 `SentinelEditor.needsReset`（`!isComposing && value != idleValue`）此时判定「状态跑偏」并回写 `setEditingState`；引擎据此认为组字结束，之后每次按键都把整段预编辑串当**已提交文本**重新插入（delta 无 composing、插入点在 0）。
  - 修法：`needsReset` 改为 `_consumed && !isComposing`（`_consumed` 由 `applyDeltas`/`update` 在真的产出 edit 时置位，`reset()` 清零）；`TerminalTextInput._settle` 先送 edit、再 `_setComposing`、最后才回写编辑状态。软键盘/Android 行为不变。
  - 验证：`flutter test .../test/input` 168 通过；`dart analyze`（lib/src/input、test/input）无问题；变异回旧逻辑时新增的 2 个用例失败（`a composition start asks for no reset`、`a Windows composition is not reset while it is open`）。真机（Windows 11 + 微软拼音）截图确认：组字以下划线画在光标处、候选窗贴其下方、提交前不送入 shell，Space/Enter/Esc/Backspace 组字中都归 IME，提交只上屏一次、退格一次删一个字符。
